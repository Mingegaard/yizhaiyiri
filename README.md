# 一宅一日

一个可继续接入正式 3D 资产与历史内容的网页游戏原型。在唐风宅院中移动、专注、完成生活任务，收藏每天的照片与卡片。书桌上的金银筒逐签收下算筹，积满后可随祥云进入「筒中奇境」。

当前庭院、房间、精灵和金银筒均为程序构建的占位资产；生活知识卡片仍为内容占位。建筑参考图只用于理解空间关系，当前场景不是经过考证的历史复原。冒险沿用用户提供的七幕实施方案，以古籍选篇《李哲》为叙事来源；原典版本、书名卷次等由内容团队核验。金银筒与祥云是游戏入口，不改写古籍情节。任务、计时、存档和场景接入代码与这些素材分开，方便美术与历史内容团队并行工作。

## 本地运行

建议使用 Node.js 24 或更新版本，以及 pnpm 11.25.0。在本项目目录执行：

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的本地地址，通常是 `http://127.0.0.1:5173`。请通过开发服务器访问，不要直接双击 `index.html`。

```bash
pnpm test        # 领域逻辑、存储及项目中的自动化测试
pnpm build       # TypeScript 检查和生产构建
pnpm preview     # 预览 dist 中的构建产物
```

构建结果在 `dist/`，可用于支持静态文件的网站托管。这个版本不依赖后端服务，也不需要 API Key。更换域名、端口或浏览器后，会进入该来源对应的另一份本地存档。

## 操作与演示

- 宅院铺满浏览器视口，以第一人称行走，不再使用俯视院落与常驻右侧计时面板。
- `W / A / S / D` 或键盘方向键：相对于当前镜头前后左右移动；看向高处或低处时，行走仍保持在地面。
- 触控板双指上下左右滑动：环顾场景，调整水平和俯仰视角。鼠标按住画面拖拽也可环顾。
- 画面不提供虚拟方向键或旋转按钮，移动使用键盘。
- 从中央书阁朝庭院的开放前口步行进入，靠近床榻后点击「在榻上打坐」，打开原书桌样式的邀请。普通打坐从床榻发起；书案只保留金银筒互动。
- 书桌上放置高 **34 厘米** 的金银筒。每枚算筹对应一根签；走近书桌并触碰筒身查看筹数。满 10 枚时，中间静态显示「似有异动」，底部为「入境」「返回」两个文字按钮；点击「入境」后由祥云转场卷入冒险。不足 10 枚时，中间两行显示「唐龟负论语玉烛酒筹鎏金银筒」「与朋友共，敝之而无憾」，底部只有「返回」。浮层右上角不设关闭按钮。每次入场消耗 10 枚，返回庭院保留当前剧情进度。
- 建筑上不悬挂常驻名称，页头也不常驻显示当前场景名。走近门口的地面圆环后，才会出现「要进入厨房吗？」或「要进入西厢房吗？」；点击提示切换，走开后提示消失。房间内靠近出口时显示「要返回庭院吗？」。
- 左下角银钩图标不设方框，有任务时轻跃并显示「晨读／朝食／外出／夕食／就寝」，完成或无任务时为「闲时」。点击字条中的地点跳转，靠近银钩后选择相伴专注或上传图片。外出字条直接提供等待银钩和上传活动图片。
- 右上角「记忆本」：打开黄历式日页，查看公历、汉字农历和逐条日常记录。照片区按活动分列，首行为小精灵来信，下方只收任务打卡照片；这里不提供独立上传入口。右下角的小轮盘可打开月历，分别选择年、月跳转，再选择带朱印的日期并「翻开此日」。无记录日期置灰，二月与闰年按实际天数显示。
- 角落工具按钮「设置与演示」：切换日常模式和演示模式。
- 右下角扬声器按钮：开关背景音乐。默认尝试自动循环播放，浏览器若限制有声自动播放，会在首次点击、触摸或键盘操作后开始。关闭选择会保存，之后不会因行走或打开面板而自行恢复；再次点击扬声器即可继续播放。背景音乐使用提供的《11月1日.mp3》，与场景、打坐和冒险页面独立，切换界面不会从头播放。

普通打坐固定在书阁正中望向庭院；银钩任务固定在对应场景：晨读在书阁、朝食与夕食在厨房、就寝在西厢卧室，外出则在庭院等待。厨房在朝食和夕食时段持续有炊烟，不受任务完成状态影响。昼夜完全跟随时间：17:00—19:30 夕阳，19:30—次日 06:00 黑夜，其余白天。移除手动昼夜入口及旧保存偏好的覆盖，仅保留原有演示时段选择。

画面只保留右下角的淡色计时；省略号或 `Esc` 可展开暂停、继续和结束。计时与暂停均锁定行走环顾。刷新保留计时、剩余时间与暂停状态，完成后恢复行走。花瓣效果不参与奖励结算。

在网址后加 `?demo=1` 也可进入演示模式，例如 `http://127.0.0.1:5173/?demo=1`。

演示模式的普通打坐与银钩相伴专注均为 **10 秒**，落瓣间隔为 **5 秒**。使用已有设置选择晨读、朝食、外出、夕食、就寝、闲时，无新增昼夜控制。演示与日常存档和照片隔离。时段选择改变任务资格和氛围，不修改已经运行的计时长度。

也可以直接打开[冒险测试链接](http://127.0.0.1:5173/?demo=1&setup=adventure)（端口以开发服务器实际地址为准）。`?demo=1&setup=adventure` 会在当前页面将演示算筹设为恰好 **10 枚**，保留其他进度。设置成功后，网址会自动移除 `setup=adventure`、保留演示模式，因此普通刷新不会再次补筹；需要再测一次时，重新打开这个完整链接即可重新设为 10 枚。已有的专注或休息不会被取消，进入冒险前仍须先结束。

建议在演示模式中依次切换五个时段：打开字条、点击地点、靠近银钩，选择专注或上传图片。前四次只展示雀跃，第五次弹出该次任务类型的知识卡；刷新后待收下的卡片仍保留。普通打坐和金银筒入境流程可以独立体验。

## 游戏规则

| 任务 | 时段 | 场景 |
| --- | --- | --- |
| 晨读 | 08:00—10:00 | 中央书阁 |
| 朝食 | 11:30—13:30 | 厨房 |
| 外出 | 15:00—17:00 | 户外图片或庭院等待 |
| 夕食 | 17:00—19:30 | 厨房，夕阳与炊烟 |
| 就寝 | 22:30—24:00 | 西厢卧室，夜晚 |

区间包含开始、不包含结束；按设备本地时间判断，演示使用已有时段预览。图片须在对应时段成功提交；专注须在同一日相应时段内开始、完成并结算。暂停导致越过窗口、过时返回、跨日或切到其他演示时段均不算完成健康任务。仅打开应用不自动完成任务。

以下结算只在状态中维护，不展示在任务字条或操作框中：每项健康任务得 1 筹，照片和专注共用每日领取状态，每日每种只结算一次。累计完成数跨日保存，每逢 5 的倍数才取一张卡，取自第 5、10、15…次任务所属类型的卡片池，同类卡池轮换。其他完成只展示银钩雀跃。普通打坐仍为 30 分钟、完成加 1 筹，不计入健康任务累计；演示均为 10 秒。

计时用时间戳计算，暂停只保存剩余时间。照片原图保存在 IndexedDB，记忆本保留日期、任务、照片和已获得的卡片。旧存档保留筹数、记忆和收藏，历史完成键用于迁移累计数，不补发旧卡。旧六小时睡眠返回机制已退役，不再据此跨时段发奖。

金银筒与冒险规则保留：初始 9 筹，满 10 筹可入境，每次消耗 10 筹。剧情保留节点与永久札记，首次通关得瓦魅纪念卡及 1 筹，之后不重复奖励。进行中的计时须先结束。

```text
  cards/                  历史卡片图片放这里
src/
  App.tsx                 页面组合、当前场景、活动推荐与操作分发
  main.tsx                React 入口
  components/             计时、活动、日历记忆本、弹窗、操作按钮

    VesselInvitation.tsx  触碰后的筹数、静态提示与「入境」「返回」操作
  content/
    activities.ts         生活任务文案、时段和对应场景
    assets.ts             场景/精灵/花树资源路径、变换与动作映射
    cards.ts              卡片图片、标题、正文和史料来源
  game/
    types.ts              存档、任务、回忆与命令类型
    engine.ts             纯状态转换、算筹与任务结算规则

    useGame.ts            React 接口、后台恢复、命令与存档连接
  story/
    content.ts            七幕节点、报告与信件、必要检视、目标和下一节点
    StoryScreen.tsx       冒险场景、故事卡片、必要检视与冒险札记

    types.ts              场景、门口、导航碰撞等类型
    config.ts             出生点、第一人称姿态、书桌范围、碰撞与固定专注镜头
    ModelAsset.tsx        GLB 加载、骨骼实例克隆、动画切换
    Blockout.tsx          可替换的庭院、房间、角色占位模型
    SceneCanvas.tsx       渲染、灯光、玩家移动、镜头、门口检测
    GardenAtmosphere.tsx  独立花树、树冠微摆与按专注进度显示的落瓣
    TallyVessel.tsx       金银筒、逐筹签与器物触碰
    VesselCloudTransition.tsx  祥云进入过渡与完成回调
    vesselMath.ts        签位分布、触碰判定与过渡进度
    StoryStage.tsx        固定第一人称的故事展示场景
    storyConfig.ts        故事镜头、物证状态和独立 GLB 接入口
tests/                    自动化测试
```

主要数据流：

```text
用户点击 / 计时结束 / 返回页面
    → GameCommand
    → useGame.dispatch
    → 读取最新存档并执行 reduceGame(state, command, now)
    → 保存状态
    → 界面与 3D 场景根据状态更新
```

3D 场景只负责表现、移动、门口与器物触碰事件，不负责发放算筹或卡片。`App` 将 `sceneId`、`elfState`、夜间状态等传给场景；场景通过 `onPortalNear` 报告附近入口、`onDeskNear` 报告书桌范围，`onVesselTouch` 报告金银筒触碰。`rods` 决定筒中签数；点击「入境」后，`vesselTransition` 开始祥云过渡；`onVesselTransitionComplete` 触发原子校验扣筹，成功后进入冒险，过渡期间刷新不会提前扣筹。`focusView` 传入有效计时进度、落瓣间隔与暂停状态，固定视角和花瓣只消费这些数据。开始、暂停、恢复、取消、刷新恢复与完成奖励仍由原有 `useGame` / `engine` 处理。

`reduceGame` 接受外部传入的时间，所以无需真的等待 30 分钟或健康任务时段也能测试边界。恢复后通过清空已完成会话、每日任务键和回忆 ID 防止重复结算。在支持 Web Locks 的浏览器中，写入会跨标签页串行进行，并在锁内重读最新存档；其他标签页通过 `storage` 事件同步。未提供 Web Locks 的浏览器只保证本标签页内串行，建议单标签页使用。

## 接入正式 3D 资产

先把资源放到 `public/models/`，例如：

```text
public/models/courtyard.glb
public/models/kitchen.glb
public/models/elf.glb
```

然后修改 `src/content/assets.ts`：

```ts
export const sceneAssets = {
  courtyard: {
    url: 'models/courtyard.glb',
    scale: 1,
    position: [0, 0, 0],
    rotation: [0, 0, 0],
  },
  // kitchen 与 west-wing 按相同结构配置
};
```

保留现有对象的类型和其他场景配置。`url: null` 使用占位模型；填写地址后，加载器会替换相应场景。资源加载期间或失败时仍显示占位场景，方便继续调试。内部资源路径以网站根目录 `public/` 的内容为起点，不在 URL 中写 `public/`。代码使用 Vite 的 base URL，支持部署到子路径。

`nodeTransforms` 可按 GLB 节点名称调整局部大小或位置，偏移量使用原始模型单位；修改发生在场景副本上。当前南侧杏树以树根为中心缩到 80%，假山及其碎石底向西移 1.2 米。调整值集中在 `src/scene/gardenLayout.ts`，`config.ts` 同步使用这些值更新行走碰撞范围。

精灵独立配置 `elfAsset.url = 'models/elf.glb'`，并把导出文件中的实际动作名称写进 `elfAsset.animations`：

```ts
animations: {
  idle: 'Idle',
  cooking: 'Cook',
  sleeping: 'Sleep',
  meditating: 'Meditate',
}
```

`away` 表示精灵不在场景中，不需要对应动画。当前状态动画按循环播放接入；特殊的一次性演出可在 `ModelAsset.tsx` 中扩展。角色和环境建议分开导出，角色的多个动作使用同一骨骼。

模型接入时还需要同步检查 `src/scene/config.ts`：

| 配置 | 作用 |
| --- | --- |
| `spawn` | 用户进入该场景时的出生位置 |
| `elfAnchor` | 精灵在该场景中的放置点 |
| `bounds` | 玩家可以移动的 X/Z 平面范围 |
| `colliders` | 玩家不能穿过的矩形区域 |
| `portals` | 门口位置、触发半径、目的场景与靠近后才显示的询问文字 |
| `EYE_HEIGHT` | 自由行走的眼睛高度，当前 1.50 |
| `study.deskPosition` / `deskRadius` | 书桌位置和专注邀请触发范围，当前半径 2 |
| `study.focusCamera` / `focusTarget` | 从书阁内望向庭院的固定专注镜头 |
| `gardenTrees` | 独立花树的位置，同时用于树干碰撞和落瓣来源 |
| `tallyVessel` | 书桌金银筒的位置、本体高度、开口及签的摆放参数 |

位置采用 Three.js 的 Y 轴朝上坐标，地面使用 X/Z 平面，旋转使用弧度。建议美术统一模型尺度、原点和朝向，再用 `assets.ts` 的变换做少量调整。环境的 `position` 是场景内位置；精灵的 `position` 是相对于 `elfAnchor` 的局部偏移，不能把世界坐标重复填入两处。故事物证、镜头与房间替换另见 `public/models/README.md` 和 `src/scene/storyConfig.ts`。

当前庭院出生点为 `[0, 0, 7]`，初始朝 `-Z` 看向中央书阁；书阁中心为 `[0, 0, -2]`，前口朝 `+Z` 开放，必须可步行进入。书桌位于 `[0, 0, -2.5]`，靠近时还会检查玩家是否身处阁内。专注镜头为 `[0, 1.65, -3.5]`，横屏看向 `[0, 1.5, 5.5]`；竖屏保留同一座位，视线转向 `[3.3, 2.1, 4]`，让一棵花树完整进入画面。正式模型应保持这个视线前方开敞，或同步调整 `study` 配置与碰撞。

`GardenAtmosphere` 独立于环境 GLB。`src/content/assets.ts` 的 `gardenVegetation.trunk`、`.canopy` 可分别接树干与树冠模型，`canopyPivot` 设置树冠摆动枢轴，`petalHeight` 设置落瓣高度。使用这套独立植被时，庭院 GLB 不应再内置同一位置的树，以免重复。树干保持固定，树冠只作轻微摆动；局部坐标约定见模型目录说明。

书桌金银筒通过同一文件的 `tallyVesselAssets.vessel` 接入，祥云通过 `.cloud` 接入。筒以底面中心为原点，本体高 0.34 米；签由 `rods` 逐根绘制，不并入静态 GLB。器物默认锚点为 `[-0.91, 0.89, -2.38]`，与 `study` 桌面位置联动。正式院落模型应去掉重叠的筒；完整的触碰区域、签口高度与过渡接口见 `public/models/README.md`。

**模型替换不会自动生成可行走区域、碰撞或传送门。** 这些由 `config.ts` 管理，因此更换外观不会改变任务规则，但模型布局改变后，需要重新对齐对应区域。当前使用简单的二维矩形碰撞，尚未实现楼梯、跳跃、复杂地形、自动寻路或物理引擎。

先接一版尺寸与布局准确的粗模，确认出生点、门口、镜头和动作，再逐步完善材质、花树与建筑细节。正式模型的贴图、骨骼、材质与性能仍需在美术交付后实机验证；当前占位资产的运行结果不能代替正式资产验收。

## 修改活动与历史卡片

活动配置位于 `src/content/activities.ts`。`ACTIVITIES` 保存标题、诗句、地点引导、所在场景和相伴文案；`activityAt(date)` 负责按本地时钟选择当前推荐活动。

| 活动 ID | 默认时间 |
| --- | --- |
| `breakfast` | 08:00—10:00 |
| `lunch` | 11:30—13:30 |
| `outdoors` | 15:00—17:00 |
| `dinner` | 17:00—19:30 |
| `sleep` | 22:30—24:00 |

以上区间包含开始时间，不包含结束时间。调整时段时同时修改 `src/game/healthSchedule.ts` 和用户可见的 `time` 文案。进行中的计时不会因为时段变化而中断。

卡片在 `src/content/cards.ts` 中维护。把图片放到 `public/cards/`，设置 `image: 'cards/文件名.webp'`，再填写标题、正文、分类和 `source` 史料来源。历史生活卡片 ID `meal`、`outdoors`、`sleep` 保留兼容；新卡按五种任务分别维护在 `healthyCardPools` 中；故事永久纪念卡 ID 为 `wamai`。

每种健康任务各有两张诗句释读卡。奖励选择逻辑在 `src/game/engine.ts` 的 `completeHealthyTask`：累计五次从本次类型池轮换取卡，实际获得的 ID 写入 `MemoryEntry.cardId`；后续可在 `healthyCardPools` 增补正式图文。记忆本根据该 ID 展示素材，无需让场景代码了解历史内容。

未配置独立插画的来信使用 `public/cards/memory-elf-scenes.png` 中的通用小精灵插画；四宫格依次为饮食、户外、安寝、读书。已有 `card.image` 仍优先显示。打卡照片保持原图，缩略格边长不超过 112 像素；仅一项或两项活动时也不会撑满照片区。

## 七幕故事的工程接口

「筒中奇境」通过金银筒与祥云进入，内部沿用完整七幕内容。故事固定第一人称为李哲，阿万与士温的经历以报告呈现。七幕依次为盗书归还、竹庭来信、冠履与自辩、烛下瓦魅、同类报复、迁居与两犬、设坛归物。春夏时间由明确按钮推进，不按设备时钟自动跳幕。故事无倒计时、无失败、无战斗，也不要求在宅院中自由行走找路。

`src/story/content.ts` 导出 `STORY_NODES` 节点注册表。当前共有 **43 个节点**，包括开场、七幕和结尾。每个节点由稳定 ID 标识，包含展示内容、当前热点、主要按钮、`nextId` 和可选的 `inspectItems` / `requiredFlags`。`opening` 为起点，`ending` 的 `nextId: null` 表示结尾。

存档使用 `GameState.story`：

```ts
interface StoryProgress {
  entryConfirmed: boolean; // 已建立可继续的冒险进度
  nodeId: string;          // 当前尚待完成的节点
  viewedFlags: string[];   // 本轮已读节点与必要检视
  collectedFlags?: string[]; // 历次已读节点与证据，供永久札记查阅
  storyCompleted: boolean;// 本轮是否完成；重新开始时复位
  rewardGranted: boolean; // 首次通关奖励已发放，永久保留
}
```

主要命令：

| 命令 | 行为 |
| --- | --- |
| `startStory` | 每次扣 10 枚；未完成时保留当前节点，已完成时重置为 `opening`，保留永久收藏 |
| `inspectStory { nodeId, flagId }` | 仅接受当前节点声明的检视项，记录已查看的细节 |
| `advanceStory { nodeId }` | 仅推进与当前 ID 相符的节点，先检查必要检视，再记入 `read:节点ID` 和证据标志 |

关闭卡片只影响界面，不发送推进命令。重复点击旧节点的按钮不会跳过下一节点。瓦魅必须明确查看眉目和衣物；河滨报告必须查看铛子，才可确认相应步骤。音频、插画或动画的完成事件不作为必需推进条件。

首次明确确认最后一个节点后，写入一条 `kind: 'adventure'`、`title: '完成一次冒险'` 的回忆，发放一次 `wamai` 卡片和 1 枚算筹。后续再次完成不会重复奖励。`storyCompleted` 表示本轮完成状态，`rewardGranted` 标记永久收藏已获得；本轮位置以 `nodeId` 为准。新一轮清空 `viewedFlags`，重新要求当前流程的必要检视，但历次札记通过 `collectedFlags` 保留。

冒险札记根据 `collectedFlags ?? viewedFlags` 显示历次已读信件与物证，使用 `rewardGranted` 显示永久收藏和解读。原文、白话、互动改编和设计解读分别呈现；没有核实的金额、逐件物品清单和原典版本不应擅自补写。犬死和碎瓦以叙事交代，不做玩家伤害操作。

从旧翻牌原型迁移时，保留算筹、日常回忆、计时和睡眠数据；移除旧 `adventure` 试验进度，补 `story: null`。原有照片 ID 与 IndexedDB 内容保持不变。

## 照片与存档

- 日常状态键：`yizhaiyiri:main:v1`；演示状态键：`yizhaiyiri:demo:v1`。
- 算筹、会话和回忆元数据保存在 localStorage。
- 照片以原始 Blob 保存到 IndexedDB 的 `yizhaiyiri-photos-v1` 数据库，元数据只保存照片 ID，避免把图片塞入 localStorage。
- 照片不会上传到服务器，也不会发送给模型服务；「上传」在这个原型中表示选择并保存到当前浏览器。
- 原型没有账号、云备份或跨设备同步。清除网站数据、部分隐私浏览模式、浏览器回收存储等都可能造成记录丢失；重要照片应在设备上保留原件。
- 存储失败会向用户显示错误；读取现有存档失败时，不会静默覆盖原存档。
- 本地时间和本地数据都由用户设备控制，适合原型与个人使用。需要可信排名、可兑换奖励或多设备同步时，应把奖励与会话结算迁移到服务端。

## 测试与后续接入

自动化测试覆盖计时边界、暂停恢复、后台恢复、跨午夜记录、每日奖励幂等、照片与计时路径共享领取状态、健康时段边界、五倍数发卡与类型卡池、冒险进入扣费、必要检视、双击不跳步、全篇节点可达、一次性通关奖励、付费再次进入与札记保留、旧存档迁移、Blob 回读以及演示存档隔离。

运行 `npm test` 和 `npm run build` 检查领域规则、存储、类型与生产构建。浏览器验收应覆盖 1440×900 横屏及 390×844 竖屏：WASD / 方向键走入书阁、双指滑动环顾、点击书桌提示触发、固定专注镜头、暂停和刷新恢复、Esc 展开操作、提前结束不发奖、完成得 1 算筹、5 秒演示落瓣、厨房任务及卡片入册、黄历式记忆本。金银筒另检查逐筹一签、靠近触碰、拖动画面不误触、10 筹门槛、单次点击不重复扣费、祥云进入、返回后的付费续玩、再次通关不重复奖励与冒险札记永久保留。

浏览器使用演示时长跑通五类任务与第五次弹卡，真实时段边界、暂停越界、跨日、过时提交由自动化测试覆盖。浏览器窄屏模拟用于检查布局，正式设备的触控板、GPU 性能与长时间待机表现需另外验收。

实际发布前还应在目标手机与电脑上检查：正式模型加载、移动碰撞、门口位置、相机视角、照片读取、长时后台恢复和存储容量。当前工程保留这些可扩展边界：后端存档服务、更多小游戏、正式角色与场景、历史卡池、音效与更完整的演出。
